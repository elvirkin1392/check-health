# Спецификация: ежедневное напоминание в часовом поясе пользователя

- **Номер:** 001
- **Статус:** реализована
- **Дата:** 2026-10-09

## Зачем

Пока у человека открыт период болезни, бот спрашивает «как самочувствие?». Расписание
этого вопроса осталось тестовым: задача создавалась с cron-строкой из шести полей, где
первое поле — секунды, поэтому вопрос приходил раз в минуту, а не раз в день. Человек
получал его каждую минуту, пока не закроет период.

Спрашивать нужно один раз в сутки и в разумное время для самого человека. «Разумное
время» зависит от часового пояса, а сервер живёт в UTC, поэтому фиче нужен пояс
пользователя — иначе напоминание приходит кому-то ночью.

## Пользовательские сценарии

### Сценарий 1 — напоминание приходит раз в день (P1)

Бот. У человека открыт период болезни. Один раз в сутки, в 12:00 по его местному
времени, бот присылает вопрос о самочувствии с кнопками «хорошо» и «ещё плохо».
После «хорошо» или закрытия периода вопросы прекращаются.

### Сценарий 2 — человек задаёт часовой пояс командой (P1)

Бот. Человек отправляет команду смены пояса. Бот отвечает, какой пояс действует
сейчас, и показывает кнопки с поясами. После выбора бот подтверждает, и напоминание
начинает приходить в 12:00 по новому поясу — не со следующего деплоя, а сразу.

### Сценарий 3 — пояс приходит из Mini App (P2)

Mini App. Человек открывает приложение и входит через Telegram. Если пояса у него ещё
нет, пояс устройства сохраняется без отдельного вопроса, и напоминание дальше считается
по нему. Если пояс уже задан — вход его не меняет, даже с устройства в другом поясе.

### Сценарий 4 — пояс неизвестен (P2)

Бот. Человек пользуется только ботом, Mini App не открывал и пояс не задавал.
Напоминание приходит в 12:00 UTC — и человек может это изменить сценарием 2.

## Функциональные требования

- **FR-1:** Напоминание о самочувствии приходит не чаще одного раза в сутки.
- **FR-2:** Время напоминания — 12:00 в часовом поясе пользователя.
- **FR-3:** Часовой пояс хранится в документе пользователя; документы без него читаются.
- **FR-4:** Команда смены пояса показывает действующий пояс и список поясов на выбор.
- **FR-5:** Mini App при входе передаёт часовой пояс устройства. Он сохраняется только
  если пояса ещё нет: выбор, сделанный человеком, не перетирается.
- **FR-6:** Пояс, который система не может распознать, не сохраняется; пользователь
  получает ответ, что пояс не распознан.
- **FR-7:** Если пояс неизвестен, напоминание считается по UTC.
- **FR-8:** Смена пояса переносит уже запущенные напоминания сразу, без перезапуска
  процесса.
- **FR-9:** Напоминания, созданные с устаревшим расписанием, исправляются сами при
  следующем старте процесса — без ручной миграции.
- **FR-10:** Все новые тексты есть на en и ru.

## Критерии приёмки

- **AC-1** (FR-1, FR-2): **Given** пользователь с поясом `Europe/Moscow` открывает период
  болезни, **When** создаётся задача напоминания, **Then** её расписание — ежедневное
  в 12:00, и 12:00 этого пояса соответствует 09:00 UTC.
- **AC-2** (FR-1): **Given** расписание напоминания, **When** его сравнивают с тестовым
  «раз в минуту», **Then** они не совпадают.
- **AC-3** (FR-7): **Given** пользователь без сохранённого пояса, **When** он открывает
  период болезни, **Then** напоминание назначается на 12:00 UTC.
- **AC-4** (FR-6): **Given** строка, которая не является часовым поясом, **When** она
  приходит как выбор пояса, **Then** пояс не сохраняется, напоминания не переносятся,
  и пользователь получает ответ о нераспознанном поясе.
- **AC-5** (FR-6, FR-7): **Given** нераспознанная строка пояса, **When** по ней считается
  расписание, **Then** используется UTC.
- **AC-6** (FR-4): **Given** пользователь без пояса, **When** он вызывает команду смены
  пояса, **Then** в тексте назван UTC как действующий, а в клавиатуре — все поддерживаемые
  пояса, каждый со своим текущим смещением.
- **AC-7** (FR-4): **Given** пользователь с поясом `Asia/Tokyo`, **When** он вызывает
  команду, **Then** в тексте назван `Asia/Tokyo`.
- **AC-8** (FR-4, FR-8): **Given** пользователь выбирает распознаваемый пояс, **When**
  обрабатывается нажатие, **Then** пояс сохраняется, запрашивается перенос запущенных
  напоминаний, и в подтверждении назван выбранный пояс.
- **AC-9** (FR-9): **Given** запись напоминания с тестовым расписанием «раз в минуту»,
  **When** процесс стартует, **Then** запись признаётся устаревшей, исправляется
  и запускается по актуальному расписанию.
- **AC-10** (FR-9, FR-3): **Given** запись напоминания, созданная до появления поля
  расписания, **When** процесс стартует, **Then** она не пропускается, а получает
  актуальное расписание.
- **AC-11** (FR-9): **Given** запись с актуальным расписанием и совпадающим поясом,
  **When** процесс стартует, **Then** запись не перезаписывается.
- **AC-12** (FR-10): **Given** пользователь с языком ru, **When** он получает ответ
  о нераспознанном поясе, **Then** текст на русском.
- **AC-13** (FR-1): **Given** пользователь отвечает «ещё плохо», **When** обрабатывается
  ответ, **Then** напоминание продолжает работать; на «хорошо» — останавливается.
- **AC-14** (FR-5): **Given** пользователь с уже заданным поясом, **When** он входит
  через Mini App с устройства в другом поясе, **Then** сохранённый пояс не меняется.
- **AC-15** (FR-5): **Given** пользователь без пояса, **When** он входит через Mini App,
  **Then** пояс устройства сохраняется и запущенные напоминания переносятся.

## Граничные случаи

- Пояс неизвестен — напоминание по UTC (FR-7), а не отсутствует.
- Пояс в документе есть, но нераспознаваемый (например, переехал из старых данных) —
  трактуется как неизвестный, то есть UTC.
- Пользователь выбирает UTC осознанно — это валидный выбор, он есть в списке.
- Пользователь меняет пояс, когда период болезни уже открыт — напоминание переезжает
  сразу (FR-8).
- Пользователь меняет пояс, когда ничего не запущено — переносить нечего, ошибки нет.
- Перезапуск процесса в любой момент — расписание восстанавливается из базы (§5).
- Одна битая запись напоминания не ломает восстановление остальных (§10).
- Переход на летнее время: 12:00 остаётся местным полднем, смещение пересчитывается.
- Человек задал пояс командой, потом зашёл в Mini App с ноутбука в другом поясе —
  его выбор сохраняется, автоматика не вмешивается.

## Не входит в фичу

- Выбор часа напоминания пользователем — 12:00 зафиксировано.
- Автоопределение пояса для тех, кто не открывает Mini App, — только команда или UTC.
- Ручной ввод пояса и поиск по списку: список фиксированный, 15 поясов (решение от
  2026-10-09 — этого достаточно).
- **Даты начала и конца болезни, «сегодня», «вчера» и статистика по-прежнему считаются
  по времени сервера (UTC).** §9 требует считать по поясу пользователя и это, но здесь
  исправлено только напоминание. Остальное — отдельная фича; пояс для неё уже есть
  в документе пользователя.
- Перечитывание пояса при каждом открытии Mini App: пояс проставляется один
  раз, дальше человек меняет его командой (решение от 2026-10-09).
- Регистрация команды в меню бота (`setMyCommands`) — в коде не вызывается. Команда
  добавлена в меню вручную через BotFather 2026-10-09.

## Открытые вопросы

Открытых вопросов нет.

### Решения (2026-10-09)

- **Список поясов.** Фиксированных 15 поясов достаточно; ручной ввод и поиск не нужны.
- **Обновление пояса из Mini App.** Достаточно проставить один раз. Дальше человек
  меняет пояс командой сам, и автоматический вход его выбор не перетирает (FR-5, AC-14).
- **Меню команд.** Команда добавлена в BotFather вручную.
