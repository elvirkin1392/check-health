# План: перевод оставшихся серверных .js в TypeScript

Спецификация: [spec.md](./spec.md)

## Обзор решения

**Решение от 2026-10-14: переводим разом, одним заходом, а не по слоям.** Файлов
пятнадцать и около 374 строк — дробить на коммиты по слоям дороже, чем проверить
результат целиком. Типизация всё равно шла снизу вверх внутри одного прохода, потому
что типы нижнего слоя задают типы верхнего.

На выходе `npm run check-ts` и `npm test` зелёные, поведение не меняется.

## Данные

Изменений в документах нет. Типы документов, которые появятся при переводе, должны
совпасть с уже описанными в `db/templates/UserTemplate.tsx` (`UserDoc`, `IllPeriod`),
а не дублировать их.

## Интерфейсы

Публичные подписи функций сохраняются. Меняются только пути импортов: при
переименовании файла все ссылки на него должны перейти на новое расширение —
проект на ESM, неверный путь падает в рантайме, а не на компиляции.

## Требования → решение

| FR | Решение |
|---|---|
| FR-1 | тесты не меняются; каждый коммит проверяется `check-ts` и `npm test` |
| FR-2 | `git mv` + типизация, по слоям снизу вверх |
| FR-3 | типы документов берутся из существующих `UserDoc` / `IllPeriod`; для Express — `Request`/`Response` |
| FR-4 | `tsconfig.json` не трогаем |
| FR-5 | один слой — один коммит; найденные ошибки — отдельными коммитами |

## Зависимости

`@types/express` переведён с `^5.0.0` на `^4.17.21`. Это не новая зависимость, а
исправление рассогласования: в рантайме стоит `express@4.21.0`, а типы описывали
пятый мажор. Из-за этого middleware `express-jwt` не сходился с `RequestHandler`
(`Promise<void | Immediate>` против `void | Promise<void>`), и ни один роут
не проходил тайпчек. Правка затрагивает только типы, на рантайм не влияет.

Проверено запуском: сервер поднимается, `GET /api/profile` без токена отвечает 401,
то есть `auth.required` работает как раньше.

`@types/jsonwebtoken` не добавлен отдельно: он приезжает транзитивно из `express-jwt`.
Если `express-jwt` когда-нибудь его уронит, `token.utils.tsx` перестанет
тайпчекаться — тогда и добавить явно.

## Что типизация вскрыла

Три ошибки, которые `allowJs` прятал. Все три исправлены так, чтобы поведение
осталось прежним — это конвертация, а не багфикс:

1. `auth.db`: второй аргумент `findOne` был `{loginCode: 1, bio: 1}` — не проекция,
   а неизвестные опции, которые mongo игнорировал. Проекция никогда не работала.
   Включать её сейчас нельзя: она отрезала бы `loginCodeExpiresAt`
   и `loginCodeAttempts`, на которых держатся срок жизни кода и лимит попыток.
   Аргумент убран, поведение прежнее.
2. `auth.controller` и `profile.controller`: `res.sendStatus(500, error)` — `sendStatus`
   принимает один аргумент, второй всегда отбрасывался. Убран.
3. `auth.service`: `padStart(4, 0)` — вторым аргументом ожидается строка. В рантайме
   `0` приводился к `"0"`, поэтому работало. Записано явно.

Плюс убраны неиспользуемые параметры `next` в `admin.controller` (их запрещает
`noUnusedParameters`); на поведение Express это не влияет.

## Мёртвый код, найденный по дороге

Не трогали, выносится отдельно: `routes/auth/auth.enum.tsx` не импортируется нигде,
`getWebhookInfo` из `telegram.api` не используется, зависимости `ws` и `express-ws`
не используются в коде.

## Риски и ограничения

- Строгие дженерики драйвера MongoDB: нетипизированные объекты обновления перестают
  проходить проверку. Решение проверено на `telegram.db` — параметризовать коллекцию
  типом документа и описать тип объекта обновления.
- Типизация Express без `@types` на результатах может потянуть за собой каскад правок
  в контроллерах; если слой окажется слишком дорогим, он откладывается с записью здесь,
  а не молча.
- Перевод может вскрыть существующие ошибки. Это хорошо, но исправление — изменение
  поведения: отдельный коммит, упоминание в этом плане.
