# План: перевод оставшихся серверных .js в TypeScript

Спецификация: [spec.md](./spec.md)

## Обзор решения

Перевод по слоям, снизу вверх: сначала то, что не зависит ни от чего (модель исключения,
утилита токена, клиент базы), потом слой запросов, потом сервисы, потом контроллеры
и роутеры. На каждом шаге `npm run check-ts` и `npm test` зелёные, поведение не меняется.

Порядок именно такой, потому что типизация нижнего слоя задаёт типы, на которые
опирается верхний: если начать с контроллеров, их придётся типизировать дважды.

## Данные

Изменений в документах нет. Типы документов, которые появятся при переводе, должны
совпасть с уже описанными в `db/templates/UserTemplate.tsx` (`UserDoc`, `IllPeriod`),
а не дублировать их.

## Интерфейсы

Публичные подписи функций сохраняются. Меняются только пути импортов: при
переименовании файла все ссылки на него должны перейти на новое расширение —
проект на ESM, неверный путь падает в рантайме, а не на компиляции.

## Требования → решение

| FR | Решение |
|---|---|
| FR-1 | тесты не меняются; каждый коммит проверяется `check-ts` и `npm test` |
| FR-2 | `git mv` + типизация, по слоям снизу вверх |
| FR-3 | типы документов берутся из существующих `UserDoc` / `IllPeriod`; для Express — `Request`/`Response` |
| FR-4 | `tsconfig.json` не трогаем |
| FR-5 | один слой — один коммит; найденные ошибки — отдельными коммитами |

## Риски и ограничения

- Строгие дженерики драйвера MongoDB: нетипизированные объекты обновления перестают
  проходить проверку. Решение проверено на `telegram.db` — параметризовать коллекцию
  типом документа и описать тип объекта обновления.
- Типизация Express без `@types` на результатах может потянуть за собой каскад правок
  в контроллерах; если слой окажется слишком дорогим, он откладывается с записью здесь,
  а не молча.
- Перевод может вскрыть существующие ошибки. Это хорошо, но исправление — изменение
  поведения: отдельный коммит, упоминание в этом плане.

## Проверка конституции

| Принцип | Соблюдён? | Комментарий |
|---|---|---|
| 1. Спека — источник правды | да | спека и план написаны до работы |
| 2. Тесты до реализации | н/п | поведение не меняется, новые тесты не нужны; существующие — страховка |
| 3. Зелёный CI | требование | `check-ts` и `npm test` зелёные на каждом коммите |
| 6. Типизация | это и есть задача | `tsconfig.json` не ослабляется |
| 7. Простота | да | новых зависимостей не предполагается; `@types/*` при необходимости — с обоснованием здесь |
| 8. Схема расширяется | н/п | документы не меняются |
