# Спецификация: перевод оставшихся серверных .js в TypeScript

- **Номер:** 000
- **Статус:** черновик
- **Дата:** 2026-10-09

## Зачем

Конституция (принцип 6) требует переводить оставшиеся `.js` в TypeScript по мере
затронутости и фиксировать отложенное решение, а не замалчивать его. Фича
[001](../001-daily-reminder-timezone/spec.md) затронула цепочку входа через Mini App
(`auth.controller.js` → `auth.service.js` → `auth.db.js`) и не стала её переводить:
за ней тянутся `token.utils.js` и `http-exception.model.js`, то есть почти весь слой
маршрутов, а это уже не часть той фичи.

Это долг, а не фича: поведение не меняется. Номер 000 — работа стоит перед
остальной очередью, потому что каждая следующая фича, которая тронет маршруты,
снова упрётся в тот же выбор.

Перевод не косметика. При переводе `telegram.db.js` в рамках 001 выяснилось, что
типизация коллекций вскрывает ошибки, которые `allowJs` прятал: в cron-слое поле
`userId` было объявлено строкой, хотя всегда содержало число — настоящая строка
означала бы, что запрос к MongoDB молча не находит ни одной задачи.

## Пользовательские сценарии

### Сценарий 1 — поведение не меняется (P1)

Пользователь бота и Mini App. Вход, команды, напоминания, статистика работают ровно
так же, как до перевода: ни одного заметного снаружи изменения.

### Сценарий 2 — ошибки видны разработчику (P2)

Разработчик правит код маршрутов. Несовпадение типов на границах (документы базы,
аргументы функций, ответы Telegram) видно из `npm run check-ts`, а не в рантайме
на проде.

## Функциональные требования

- **FR-1:** Поведение приложения не меняется ни в одном сценарии.
- **FR-2:** Оставшиеся серверные `.js` переименованы в `.ts`/`.tsx` и типизированы.
- **FR-3:** На границах (документы MongoDB, апдейты Telegram, аргументы и результаты
  функций) типы описаны; `any` не остаётся.
- **FR-4:** Настройки `tsconfig.json` не ослабляются.
- **FR-5:** Перевод делается отдельными коммитами, не смешанными с изменениями поведения.

## Критерии приёмки

- **AC-1** (FR-1): **Given** существующие тесты, **When** перевод завершён, **Then** они
  проходят без изменений самих тестов.
- **AC-2** (FR-2, FR-4): **Given** переведённый код, **When** запускается
  `npm run check-ts`, **Then** он зелёный без правок `tsconfig.json`.
- **AC-3** (FR-2): **Given** репозиторий после работы, **When** считаются серверные `.js`
  (без `coverage/` и конфигов), **Then** их не осталось.
- **AC-4** (FR-5): **Given** история ветки, **When** смотрят коммиты перевода, **Then**
  в них нет изменений поведения.

## Граничные случаи

- Файл, который импортируется по расширению `.js` — после переименования все импорты
  должны указывать на новое имя, иначе рантайм падает (ESM, `"type": "module"`).
- Строгая типизация драйвера MongoDB конфликтует с нетипизированными объектами
  обновления: коллекции нужно параметризовать типом документа.
- Типизация может вскрыть существующие ошибки (как с `userId`). Исправление такой
  ошибки — изменение поведения, поэтому идёт отдельным коммитом со своим обоснованием.

## Не входит в фичу

- `client/` — там уже TypeScript.
- `coverage/` — сгенерированные артефакты. (Отдельный вопрос: зачем они в гите.)
- `jest.config.js` и прочие конфиги сборки.
- Усиление настроек `tsconfig.json` (`strictNullChecks`, `noImplicitAny`) — конституция
  называет это отдельной задачей.
