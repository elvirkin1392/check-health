Аргументы: $ARGUMENTS

1. Определи папку фичи (аргумент или последняя в specs/). Прочитай spec.md, plan.md, tasks.md.
2. Если существует .claude/tests.lock — тесты заблокированы. Остановись и скажи пользователю
   разблокировать их в терминале: `rm .claude/tests.lock`.
3. Выполни задачи фазы «Тесты» из tasks.md:
   - по одному или несколько тестов на каждый AC; в названии теста укажи номер: `test('AC-2: …')`;
   - файлы *.test.tsx рядом с тестируемым модулем, стиль как в существующих тестах (Jest + ts-jest);
   - тестируй поведение из спеки, а не детали реализации; моки только на границах (Telegram API, MongoDB);
   - если для теста нужна сигнатура ещё не существующей функции — возьми её из plan.md
     и создай минимальную заглушку, которая бросает `new Error('not implemented')`.
4. Запусти тесты. Новые тесты должны падать по правильной причине (не реализовано), а не из-за ошибок в самих тестах.
5. Отметь задачи фазы «Тесты» `[x]`.

В конце: таблица AC → тест (file:line) и результат прогона.
Попроси пользователя просмотреть тесты: после `/sdd-implement` они будут заблокированы.
