description: SDD шаг 4 — заблокировать тесты и реализовать задачи через субагента implementer
argument-hint: [specs/NNN-slug]
---
Аргументы: $ARGUMENTS

1. Определи папку фичи (аргумент или последняя в specs/). Прочитай tasks.md.
   Если задачи фазы «Тесты» не отмечены `[x]` — остановись и предложи сначала `/sdd-tests`.
2. Заблокируй тесты: выполни ровно `touch .claude/tests.lock`.
3. Раздели невыполненные задачи фазы «Реализация» на небольшие последовательные пачки (зависимые задачи — в одну пачку).
   Каждую пачку передай субагенту `implementer`, указав папку фичи и номера задач.
   Задачи с [P], не пересекающиеся по файлам, можно отдавать параллельно.
4. После каждой пачки сам проверь результат: `npm run check-ts`, `npm test`
   (и `cd client && npm run lint && npm test`, если менялся client/). Если красное — верни субагенту с выводом ошибок.
5. Если субагент сообщает, что тест неверен или противоречит спеке — остановись и спроси пользователя.
   Сам тесты не трогай: их правит только пользователь после `rm .claude/tests.lock`.
6. Выполни фазу «Проверка» из tasks.md (кроме ручной проверки — её опиши пользователю по шагам).

В конце: выполненные задачи, изменённые файлы, результаты проверок.
Предложи запустить `/sdd-review`. Тесты остаются заблокированными.
