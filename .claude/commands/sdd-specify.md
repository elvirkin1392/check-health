Создай спецификацию новой фичи по описанию:

$ARGUMENTS

Шаги:
1. Прочитай specs/constitution.md и specs/_templates/spec.md.
2. Найди следующий свободный номер в specs/ (001, 002, …) и придумай короткий kebab-case slug.
   Создай specs/NNN-slug/spec.md по шаблону.
3. Изучи существующий код ровно настолько, чтобы понять текущее поведение, которое фича затрагивает
   (бот, Mini App, API, cron). В спеке описывай поведение, а не код.
4. Заполни спеку:
   - пользовательские сценарии с приоритетами (P1 — без него фича бессмысленна);
   - функциональные требования FR-1, FR-2, … — проверяемые, по одному поведению на пункт;
   - критерии приёмки AC-1, AC-2, … в формате Given / When / Then — каждый должен превращаться в тест;
   - граничные случаи и что явно НЕ входит в фичу.
5. Всё, что ты додумываешь, помечай `[NEEDS CLARIFICATION: вопрос]`. Не угадывай.
6. Никаких названий библиотек, файлов, таблиц и эндпоинтов — это для plan.md.

В конце: покажи путь к файлу, краткое резюме и списком все `[NEEDS CLARIFICATION]` вопросы,
чтобы пользователь ответил. Код не пиши.
